# 13 回合制改造

> **一个回合 = 一季 = 30 天。** 邻格 1 回合，远处的格子按途经格数算。
> 复现：`./tools/godot.sh --headless --script res://tools/debug_turns.gd`

## 13.1 为什么改

不是"回合制更流行"，是**我们自己的代码已经在往那个方向跑了**，四条证据都在已有的实现里：

1. **我写了 7 条自动暂停规则**（[06.1](06-玩法循环与玩家体验.md)）：灾祸前兆、蜕变窗口、妊娠结果、迁徙抵达、发现遗迹、指标跌破、个体死亡。
   一个实时游戏需要 7 条自动暂停规则，说明它其实是个还没承认自己是回合制的回合制游戏。
2. **经济模型本来就是季度性的**：采集系数 春 1.0 / 夏 1.15 / 秋 1.3 / **冬 0.45**，生长系数 冬 0.15。
   真正有意思的粒度**已经是"季"了**，日 tick 只是把一个季度边界上的决策做了 30 次细粒度积分。
3. **所有决策本来就是离散的**：配对、派工、迁徙、蜕变——没有一个需要日内分辨率。
4. **肉鸽本来就是回合制的**：FTL、杀戮尖塔、文明、陷阵之志。实时暂停型的肉鸽很少，因为它一直在跟形式对抗。

## 13.2 最关键的一条：零返工

> **回合制不是把模拟粒度变粗，而是在日结算外面套一层决策边界。**

```
回合开始时：跑 30 次 tick_day()   ← docs/11 标定的东西一行都没改
            ↓
回合结束时：停在决策点，等玩家
```

`WorldState.end_turn()` 就是"跑 30 次 `tick_day()`，然后 `turn += 1`"。
所以 [docs/11](11-资源耗竭与迁徙节奏实测.md) 辛苦标定的**「第 24 分钟被迫迁徙」直接平移成「第 24 回合」**，数值零返工。
测试工具也一样，`for _d in 960` 换成 `for _t in 32` 就行。

**实测 8 个随机大陆：**

| 种子 | 起点承载力 | 土地跌破两成 | 现实分钟 @1x | 灭绝 |
|---|---|---|---|---|
| 11 | 17.6 | 第 24 回合（6.0 年） | 25 | 35 |
| 22 | 17.4 | 第 30 回合（7.5 年） | 31 | 41 |
| 33 | 17.0 | 第 26 回合（6.5 年） | 27 | 38 |
| 44 | 18.2 | 第 23 回合（5.8 年） | 24 | 35 |
| 55 | 17.0 | 第 22 回合（5.5 年） | 23 | 33 |
| 66 | 17.4 | 第 22 回合（5.5 年） | 22 | 32 |
| 77 | 17.4 | 第 20 回合（5.0 年） | 20 | 28 |
| 88 | 17.1 | 第 26 回合（6.5 年） | 26 | 37 |

**最小 20、中位 24、最大 30 —— 全部落在 15–40 回合的目标窗口内，中位数正好是第 24 回合。**

## 13.3 在途状态机（方案 A）

既然「邻格 1 回合」，那 **1 格 = 1 回合**，旅途天数直接变成回合数。迁往远处会进入**在途**状态：

| 在途时 | 效果 |
|---|---|
| 生产 | 没有工作点、没有猎场，只能边走边采：每人每日产出 ×0.55 |
| 土地 | **不消耗任何节点**（我们已经离开了），离开的节点反而在恢复 |
| 配对 | 全部停止（休息所、法术都不行） |
| 迁徙距离 | 邻格 = 1 回合；3 格远 = 3 回合，途中会显示「途经：暗滩 → 松门 → 松滩」 |

实测一次 3 回合迁徙（12 人）的粮仓曲线：

```
出发前 540
第 1 回合 355      在途，剩 2 回合
第 2 回合 177      在途，剩 1 回合
第 3 回合   3      抵达 松滩
```

**一次 3 回合的迁徙会吃掉整个粮仓。** 这是刻意的：**迁徙前必须囤粮**，
而"囤粮"这件事本身又会加速把脚下的土地吃空 —— 两条压力线在这里合流。

这也让 [docs/04.6](04-部落经营与迁移.md) 里"旅途"那一段真正有了载体：
背景音乐停掉、只剩脚步和风、每回合都要吃饭、走错方向就是全族饿死。

## 13.4 动画变成了「回执」

改造前：兽人在背景里持续移动。**看 10 分钟就变成壁纸，你会停止注意它。**

改造后：按下「结束回合 ▶」→ 播放三阶段结算动画 →

```
① 出发（0.85 秒）  所有人从营地走向自己被指派的工作点
② 干活（1.30 秒）  头顶转金色采集环，画到工作点的连线
③ 返回（0.85 秒）  回到营地
   ↓
动画结束才真正推进 30 天并刷新数字
```

**顺序很重要**：动画展示的是"这一回合你派他们去干了什么"，然后才结算。
动画从背景变成了**你决策的回执**。

无头自检会设置 `skip_animation = true` 跳过（否则 32 回合的自检要跑 100 秒），
这个坑值得记一笔：**表现层的时长会直接拖慢开发循环，一定要留一个跳过开关。**

## 13.5 现在的一回合长什么样

```
① 结算（自动）：上回合派出去的人产出 → 消耗 → 受孕判定 → 灾祸推进 → 年龄
② 决策（你）：  派工 / 配对 / 建造 / 研究 / 外交 / 迁徙
③ 结束回合：    播放动画 → 推进 30 天 → 季节前进一档
```

| 单位 | 换算 |
|---|---|
| 1 回合 | 1 季 = 30 天 |
| 1 年 | 4 回合 |
| 首次被迫迁徙 | 第 **24** 回合 |
| 一局 8–12 世代 | 120–180 游戏年 = **480–720 回合** |
| 每回合 30–60 秒 | **8–15 小时** ← 正好对上 [docs/06](06-玩法循环与玩家体验.md) 的单局时长 |

## 13.6 地图太小 —— 不是尺寸问题，是**形状**问题

第一次把大陆图做出来之后，第一反应是"面板太小"，但调面板尺寸没用。真正的原因有两层：

**① 中栏永远是又宽又扁的。** 1440×900 的窗口里，左栏 330 + 右栏 330 拿走了 660，
剩下的中栏还要纵向分给谱系规划器、按钮行、信息面板 —— 地图只剩 580×285。
而适应窗口的缩放是 `min(宽比, 高比)`，所以地图被**高度**卡死，六边形只有 21px 半径。

**② 大陆是竖着的。** 六边形网格半径 4 的天然宽高比约 **1.15**（接近正方形），
放进 580×285 的横条面板里，左右会空出一大片，而格子还是那么小。

两处都改：

| 改动 | 效果 |
|---|---|
| **全屏地图按钮**（Esc 退出） | 收起左右栏、底部日志、地图下方所有控件，地图铺满整个窗口 |
| **大陆改成横向椭圆**（宽:高 ≈ 1.7） | 同样的面板能多出三成的格子尺寸 |
| **滚轮缩放 + 右键平移 + 双击复位** | 想看哪块放大看，不再受面板比例限制 |

改完六边形半径从 21px → 54px → **69px**，格子名字和承载力都看得清了。

> **教训：一个"太小"的界面问题，第一反应往往是调尺寸，但真正的约束常常是长宽比。**
> 地图类视图必须先问「我的内容是什么形状」，再决定容器怎么切。

## 13.7 顺手抓到的两个 bug

**① 工作点的工人名单会「旧一步」。**
`_sync_sites()` 在每个 tick 开头重建名单，但**饥饿和衰老会在同一个 tick 里把人杀掉** ——
于是名单里留着已经死掉的人的 id。而 `_refresh_site_info()` 每帧都在读它，
一访问 `beasts[id]` 就报 *Invalid access to property or key '24'*，并且**每帧刷一次，满屏都是**。

修法三处：反查时加 `beasts.has(id)` 守卫、`site_workers()` 过滤、`tick_day` 结尾再同步一次。

**② 界面在每帧全量重建。**
`_process` 里调 `_refresh()`，于是一个"陈旧数据"的小错被放大成了每秒 60 次的报错洪水。
回合制下界面只需要在「结束回合」和交互时刷新，地图视图各自 `queue_redraw` 就够了。

> **教训：把报错刷成满屏，比报错本身更掩盖问题。** 高频调用的路径上放全量刷新，
> 会让任何一个小 bug 都变成噪音。

## 13.8 字体太小 —— 别逐个改字号，用全局缩放

第一反应是"把字号调大"，但那是错的方向：界面里有几十处字号（`_mk_label` 的调用、
按钮的 `add_theme_font_size_override`、两个地图视图里 `draw_string` 的字号），
逐个改一定会漏，而且以后每加一个控件都要记得放大。

正解是 Godot 的 **`content_scale_factor`**：

```gdscript
get_window().content_scale_mode = Window.CONTENT_SCALE_MODE_CANVAS_ITEMS
get_window().content_scale_factor = ui_scale      # 默认 1.25
```

一行把整个界面（字体、间距、两个地图）一起放大。顶栏加了 **A− / A+** 让玩家自己调。

### 但光放大界面会把布局搞崩

缩放从 1.0 提到 1.35 之后：

- **顶栏出界**了（"重开"按钮跑到屏幕外）→ 顶栏改成 `HFlowContainer` 自动换行
- **三栏布局挤爆**：右栏文字被裁、谱系规划器被整个推出屏幕
- **大陆图上的格子名全部消失**

最后一条最值得记：`_draw` 里判断"格子够不够大才画名字"用的是**画布单位**。
`content_scale_factor` 会把画布整体放大，于是画布里的格子变小了、跌破了阈值，
**界面上看起来格子明明更大了，名字反而没了。**

修法：阈值必须按**屏幕像素**判。

```gdscript
var screen_hsize := hsize * ui_scale    # 而不是 hsize
if screen_hsize > 34.0: draw name
```

### 最终的布局

| 项 | 值 |
|---|---|
| 默认窗口 | 1600×1000（原 1440×900） |
| 默认 UI 缩放 | 1.25×，可用 A− / A+ 调 |
| 中栏 | **营地 / 大陆 / 谱系** 三个标签页 |

把谱系规划器单独开一页是最后一处关键调整：它的内容长度是**可变的**
（最多 6 条血脉 + 嵌合 + 近交 + 突变 ≈ 12 行），挂在纵向布局底部一定会把别的东西顶出屏幕。
**内容长度可变的区块不该和固定高度的区块挤在同一条轴上。**

## 13.9 遗留

- **速度档已删除**，但 `REAL_SECONDS_PER_DAY_1X` 这个常量还在被"现实分钟"换算用着 —— 现在它只是给开发者看的参考值
- `migrate_to()`（即时版）还留着给旧工具用；游戏里走的是 `start_migration()` + 在途状态机
- 迁徙途中还**没有**旅途事件（劫掠、迷路、内部冲突、遇到其他迁徙部落），
  那是 [docs/04.6](04-部落经营与迁移.md) 阶段三的内容，也是回合制下最值得补的一段
