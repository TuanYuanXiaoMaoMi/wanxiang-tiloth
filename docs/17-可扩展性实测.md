# 17 可扩展性实测

> 这一份不是设计文档，是**实测报告**。
> "可扩展性"靠读代码判断不出来 —— 得真的加一遍，数改了几个文件几行。
> 下面每个数字都是加出来的。

## 17.1 实测：加一样东西要动几处

| 想加什么 | 实测改动 | 报错 |
|---|---|---|
| **一条血脉** | `data/genetics.json` **1 个文件，0 行代码** | 0 |
| **一个生物群系** | `data/biomes.json` 1 个文件 | 0 |
| **一组嵌合** | `data/genetics.json` 1 个文件 | 0 |
| **一个知识节点**（复用已有效果键） | `knowledge.gd` **1 个文件，+10 行** | 0 |
| **一个知识节点**（新效果键，机制已存在） | `knowledge.gd` + 读取点 **1 行** = 2 文件 | 0 |
| **一种继嗣制度** | `descent.gd` +10、`tribe.gd` +18、`knowledge.gd` +N = **3 文件** | 0 |
| **一种继嗣制度的界面** | **0 行**（界面遍历 `ALL_MODES`） | 0 |

最后一行最值得说：加第七种制度时，**`game/main.gd` 一行都没改**。
制度的下拉框、改制按钮、档案显示全是遍历生成的。

## 17.2 三条让这件事成立的设计

### ① 内容即数据，门槛也是数据

知识树的节点是纯字典：

```gdscript
&"rationing": {
    "name": "配给制度", "branch": Branch.LIVELIHOOD, "tier": 2,
    "requires": [&"storage"], "trigger": {"kind": "deaths", "value": 2, ...},
    "cost": 58.0,
    "desc": "按人头分粮。真正饿死的人会少很多。",
    "effects": {"starve_debt_mult": 0.45},
},
```

加这一条，界面、触发、前置、开销、文案全部自动生效。

### ② 测试断言**不变量**，不断言**内容**

实测时撞到一个反面教材：

```gdscript
check(BloodlineDB.bloodline_ids().size() == 16, "16 条血脉")   # ✗
```

**加一条血脉（本来只是改数据）会让测试挂掉。** 已改成：

```gdscript
var nc := BloodlineDB.clade_ids().size()
check(BloodlineDB.chimera_count() == nc * (nc - 1) / 2, "嵌合组数恰好覆盖所有类群对")
```

> **内容会变，不变量不该变。** 把规模写进断言，等于给数据层上了一把锁。

现在往 `genetics.json` 里加血脉，126 项测试全过。

### ③ 新内容自动被已有测试验证

加第七种「两可继嗣」时我**没写任何新测试**，但这四条自动跑了：

```
✓ 制度「两可继嗣」有知识可以解锁      ← 遍历 ALL_MODES
✓ 所有前置知识都存在                  ← 遍历 requires
✓ 前置的层级严格小于自身（无环不倒挂）
✓ 未经历事件时不该触发：两可继嗣      ← 喂空统计计数器
```

**约束写一次，之后每加一样东西都自动被查一遍。**

## 17.3 实测撞出来的三个问题

### ① `k_value` 类效果键被两个节点重复定义 → 静默不确定

实测加「水囊」时撞到的。它和「迁徙知识」都设 `transit_forage`：

```gdscript
func k_value(key, default_value):
    for id in adopted:
        if Knowledge.effects_of(id).has(key):
            return float(Knowledge.effects_of(id)[key])   # 返回第一个匹配
```

**结果取决于字典遍历顺序。** 不确定，而且不报错。

修法两条：效果键明确分成「可叠加」（`k_mult`）和「单选」（`k_value` / `k_flag`），
并加一条测试守住：

```gdscript
check(dup_keys.is_empty(), "单选类效果键没有被两个节点重复定义")
```

### ② 测试写死了内容规模（见 17.2 ②）

### ③ 存档在静默腐烂 —— 已修，见 [docs/18](18-存档与确定性.md)

## 17.4 一处结构性的上限

加「两可继嗣」（随氏族更大的那一方姓）时撞到了静态表的边界：

```gdscript
static func child_surname(mode, father_name, father_surname, ...) -> String
```

**它是 static 的，拿不到部落状态**，数不出两边氏族各有多少人。所以这条规则
没法待在静态表里，只能在 `Tribe.surname_for()` 里开一个分支：

```gdscript
if descent_mode == Descent.Mode.AMBILINEAL:
    var cf := _group_size(father_surname)
    var cm := _group_size(mother_surname)
    ...
```

> **数据表能表达"固定规则"，表达不了"依赖世界状态的规则"。**
> 这是这套架构明确的上限：一旦某个制度要看人口、看关系、看地盘，它就必须离开表、
> 变成代码。表越长，这个边界越容易被忽略。

## 17.5 真实的可扩展性地图

| 区域 | 状态 | 说明 |
|---|---|---|
| **血脉 / 生物群系 / 嵌合** | 🟢 纯数据 | 改 JSON，有引用校验 |
| **姓名素材** | 🟢 纯数据 | 四个池子 + 类群偏好表 |
| **性情** | 🟢 基本纯数据 | 加表项即可；**但新效果键要挂读取点** |
| **知识节点** | 🟢 1 文件 10 行 | 新效果需要读取点 |
| **继嗣制度** | 🟡 3 文件 | 依赖世界状态的规则要写代码 |
| **灾祸系统** | 🔴 零实现 | [docs/05](05-灾祸与活世界.md) 设计了 22 种，一行没写 |
| **多部落 / 外交** | 🔴 静态标签 | 地图上有 `iron_fang`、`feather_burial` 等势力名，但不参与模拟 |
| **战斗** | 🔴 无 | 连数据结构都没有 |
| **事件系统** | 🟡 纯文本日志 | `_say()` 拼字符串，没有事件对象，无法被查询或回放 |
| **存档 / 读档** | 🟢 全量 + 轨迹测试守住 | 见 [docs/18](18-存档与确定性.md) |

## 17.6 结论

**模拟层的可扩展性是好的**，而且是**有证据的好**：加一种继嗣制度 = 3 个文件 55 行、
界面 0 行、测试自动覆盖。这靠的是三件事 —— 内容即数据、测试断言不变量、新内容自动被已有约束验证。

**两处结构问题，一处已修**：

1. ~~**存档层在静默腐烂。**~~ **已补完**（[docs/18](18-存档与确定性.md)），
   并由轨迹测试 + 棘轮测试守住，不会再烂回去。
2. **没有事件对象。** 所有"发生了什么"都是 `_say()` 拼出来的字符串。
   灾祸、旅途事件、外交这些系统一旦要写，都会撞上这一点 ——
   **你没法对一段字符串做条件判断**。

按"接下来该做什么"排序，我的建议是：

1. ~~补存档~~ **已完成**，见 [docs/18](18-存档与确定性.md)
2. **事件对象**（把 `_say()` 换成 `Event{turn, kind, actor, target, data}`）—— 灾祸系统的地基
3. 灾祸系统（[docs/05](05-灾祸与活世界.md) 的 22 种）
4. 联姻入口（[docs/15](15-继嗣制度.md) 15.8 说了三遍的那个）
