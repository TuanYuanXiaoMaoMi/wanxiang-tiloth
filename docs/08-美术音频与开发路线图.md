# 08 美术音频与开发路线图

## 8.1 核心美术难题：混血个体的外观怎么画

这是本作**最大的美术风险**。16 条血脉两两混血有 120 种组合，加上血浓是连续值，理论外观状态是无限的。全手绘不可能。

### 解决方案：部件组合 + 参数化着色

**思路**：不画"猫人""鹰人"，只画"耳型""尾型""角""翼""瞳""花纹"这些**部件**，然后由血脉参数驱动拼装。

| 部件层 | 变体数 | 由什么驱动 |
|---|---|---|
| 基础体型 | 3（小/中/大） | 血浓加权平均的体魄 |
| 姿态/骨架 | 4（静立/劳作/战斗/睡眠） | 当前行为 |
| **耳型** | 8 | 最高血浓血脉所属类群 |
| **吻部** | 4 | 最高血浓血脉 |
| **瞳型** | 5 | 最高血浓血脉 |
| **尾型** | 7 | 类群 |
| **角/棘/冠** | 6 | 角类、鳞类、羽类血浓 ≥35 时叠加 |
| **翼** | 3 | 羽类血浓 ≥35；≥60 时为大翼 |
| **鳞片覆盖** | 3（无/局部/全身） | 鳞类血浓分档 |
| **毛皮底色** | 连续 | 各血脉 `hue_base` 按血浓加权混合 |
| **花纹** | 6 种 mask | 最高血浓血脉的 `pattern` |
| **饰品/部落标记** | 可扩展 | 部落文化与图腾 |

组合数：`3 × 8 × 4 × 5 × 7 × 6 × 3 × 3 × 6 = 1,088,640` 种基础组合，**由约 120 张部件图 + 一个着色 shader 支撑**。

### Godot 实现

```gdscript
# 立绘 = 一叠 Sprite2D，按固定图层顺序（z_index）堆叠
# 每个部件通过 shader 参数接收：色相偏移、花纹颜色、花纹强度
#
# art/shaders/portrait_blend.gdshader
shader_type canvas_item;
uniform float hue_shift : hint_range(-0.5, 0.5) = 0.0;
uniform vec4  pattern_color : source_color = vec4(1.0);
uniform float pattern_strength : hint_range(0.0, 1.0) = 0.0;
uniform sampler2D pattern_mask : hint_color;
```

**关键工程要求**：
1. **先定部件规范表**（每张图的锚点、画布尺寸、图层顺序、可着色区域）。这张表必须在**画第一张图之前**定完，否则后期重画成本极高。
2. **混合值必须量化后再渲染**。人眼分不清血浓 62 和 63 的色相差异，但缓存会因为这个差异失效。把血浓按 5 一档量化成 21 档，缓存命中率会高得多。
3. **缓存渲染结果**。同一部落里多个个体的部件组合可能相同，用 `(部件组合 key)` 做纹理缓存。
4. 列表小头像用**同一套系统的低分辨率版本**，保证"玩家不看数字也能看出血脉变化"。

### 立绘的两种品质层

| 层 | 用途 | 成本 |
|---|---|---|
| **程序化组合立绘** | 全部个体、列表头像、地图单位 | 一次投入，无限产出（约 120 张部件图） |
| **手绘关键立绘** | 仅用于：酋长/开创者、达成终局的个体、编年史插图 | 少量，10–30 张 |

**取舍**：绝大多数个体用程序化组合。玩家真正会记住的那 5–10 个兽人，用手绘立绘做"英雄时刻"。**这个混合策略能让美术预算下降一个数量级，而情感冲击力几乎不损失。**

## 8.2 音频方向

| 层 | 内容 |
|---|---|
| **环境层** | 每个 biome 一套：风、虫鸣、水流、落叶、雪压枝。用交叉淡入切换，不要硬切 |
| **部落层** | 不和谐但温暖的复调人声吟唱（非语言，避免文化指向过强）。**人口越多，人声声部越多**——这是免费的"我的部落变大了"反馈 |
| **魔素层** | 污染越高，低频嗡鸣越明显；魔潮期加入相位失真 |
| **迁徙** | **完全没有背景音乐**。只有脚步、风、零星的风声乐器。直到新营地建立，音乐才回来 |
| **事件音效** | 灾祸前兆用**反向混响**（听起来"不太对"），爆发用低频冲击 |
| **编年史** | 世代更替时一段 20 秒的合唱，每年音调不同（用同一个动机做变奏，十年后听起来像同一个部落长大了） |

**音频预算建议**：1 名兼职音频/外包，20–30 段环境循环 + 8 段音乐 + 音效库。这是独立项目可控的规模。

## 8.3 开发路线图

### M0 · 纸面验证（1–2 周）

**不给任何画面。** 用 Excel / Google Sheets 或一个 50 行的 GDScript 脚本，模拟一个封闭部落 20 代的遗传。

| 必须验证 | 通过标准 |
|---|---|
| 封闭部落在 3–4 代内 I 系数 > 0.25 | 成立 |
| 有意规划配对能稳定跨 10 代 | 成立 |
| 随机配对会走向灭绝或血脉稀薄 | 成立 |
| 嵌合触发率是"需要努力才能达到"而不是"随手就有" | 精英个体嵌合率 40–70% |
| 纯血与混血有清晰的取舍（不是一边倒） | 双方各有优势场景 |

**如果 M0 的表格不好玩，不要写任何代码。** 这一条是本路线图里最重要的建议。

### M1 · 垂直切片（6–10 周）

**范围**：1 个区域、3 个节点、**4 条血脉**（家猫、狼、狐、鹰）、8 个兽人、采集与狩猎、繁衍、**谱系规划器**、1 种灾祸（严冬）、**1 次完整迁徙**。

| 交付 | 验证目标 |
|---|---|
| `sim/` 层 + headless 平衡模拟 | 能在命令行跑 200 代并输出直方图 |
| 采集/狩猎资源曲线 | 玩家会在第 15–25 分钟自己发现猎物在掉 |
| 谱系规划器 | **一个没看过说明的人能在 30 秒内做出一对配对决策** |
| 迁徙五阶段 | 完整走完一次；"留下谁"的界面能让人犹豫超过 10 秒 |
| 世代更替 + 编年史 | 文本生成没有明显的语法错乱 |

**M1 的验收标准只有一条**：给一个完全没听过这个游戏的人玩 30 分钟，他会不会自己说出一句"我得搬走了"。如果不会，问题在资源曲线，不在内容量。

### M2 · 系统完整（3–4 个月）

- 16 条血脉 / 7 类群 / 21 组嵌合全部实装
- 9 个魔法学派 + 交叉学派 + 魔素污染
- 四条进化路线 + 部落进化三选一
- 6 个地理区 / 60 个节点 / 5 类灾祸全部实装
- 六大势力 AI + 外交 + 联姻
- 部落分裂与亲族关系衰减
- 完整的 `kinship()` pedigree 路径计数替换近似实现

### M3 · 世界演化与内容（3–4 个月）

- 地脉潮汐（小潮/大潮）、世界季度结算
- 遗迹系统（四类）+ 考古与化石血脉
- 异血系统、返祖事件、缺陷系统全部实装
- 四种终局 + 元进度血脉种子
- 编年史导出、族谱可视化
- 事件卡内容量产（目标 200+ 张）

### M4 · 打磨与发布准备（2–3 个月）

- 部件组合立绘全面替换占位图 + 关键角色手绘立绘
- 音频制作
- 平衡（用 `balance_sim.gd` 跑数千局，检查四种终局的达成率分布）
- 本地化（zh_CN + en）
- 模组加载器与文档
- 成就、无障碍、色盲可读性审查、手柄支持

### 里程碑风险控制

| 风险 | 对策 |
|---|---|
| 内容量爆炸 | M1 只做 4 条血脉。**血脉数量是最后才加的，不是最先** |
| 遗传不平衡 | M0 纸面验证前置。**不平衡就不写代码** |
| 美术做不完 | 程序化组合方案从 M1 就搭起来，先用色块占位 |
| 玩法不好玩 | M1 结束后做一次真实用户测试，如果反应是"不知道该干嘛"，先改资源曲线 |

## 8.4 技能与工作量估算

| 角色 | 工作量 | 备注 |
|---|---|---|
| 程序（GDScript / 系统设计） | 1 人，全职 10–14 个月 | 核心；`sim/` 层需要有人能写出可测、无节点依赖的代码 |
| 系统/数值设计 | 与程序同一人可兼任，但需额外 2–3 个月专门调平衡 | `balance_sim.gd` 的产出必须有人读得懂 |
| 2D 美术 | 部件图约 120 张 + 关键立绘 10–30 张 + UI | 可外包部件图（规范明确，外包风险低）；关键立绘必须自己控 |
| 音频 | 20–30 环境循环 + 8 音乐 + 音效 | 兼职或外包 |
| 文案 | 事件卡 200+、编年史模板、世界观 | 量大但可增量产出；**编年史必须模板化** |

**最小可行版本（M1 可玩切片）**：1 人 × 2 个月，美术全部用色块和免费素材，把**遗传 + 资源曲线 + 迁徙**三个系统的"手感"验证出来。这是投入产出比最高的第一步。
