# 16 知识树：部落不是"人口到了就学会"，而是经历了才想明白

> 二十二个知识节点，两把锁 —— **前置知识**（树结构）与 **触发条件**（必须真实发生过某件事）。
> 发现不等于采纳，玩家自己决定花不花信仰。
> 复现：
> ```bash
> ./tools/godot.sh --headless --script res://tools/debug_knowledge.gd  # 发现流程与效果
> ./tools/godot.sh -- --screenshot-knowledge                            # 知识界面
> ```

## 16.1 两把锁

一开始想的版本是"人口到 14 就解锁母系氏族"。但那不叫知识，那叫**计时器** ——
玩家没有做任何事，只是等，格子自己就亮了。

改成两把锁：

| 锁 | 作用 | 例子 |
|---|---|---|
| **前置知识** | 树结构。没学会走的，学不会跑的 | 双系继嗣需要母系 + 父系都采纳了 |
| **触发条件** | **必须在模拟里真实发生过某件事** | 第一个畸形儿出生，部落才第一次意识到近亲结合会遭报应 |

触发条件的文案是**给玩家看的**，而且要说清楚"为什么现在能想到这个了"：

```
第一个畸形儿出生了。没人说得出为什么，但大家开始避开血亲。
```

## 16.2 发现 ≠ 采纳

三种状态：

| 状态 | 界面 | 含义 |
|---|---|---|
| 未发现 | `？？？` | 连是什么都不知道。**开销也不显示**——那等于剧透 |
| 已发现 | `已发现` | 想到了，但前置没齐或信仰不够 |
| 可采纳 | `可采纳` | 前置齐了、信仰够了，可以花信仰学 |
| 已采纳 | `已采纳` | 生效中 |

**未发现的节点显示为 `？？？` 而不是藏起来。** 这样玩家能看见树有形状、
知道"这条路前面还有东西"，但不知道那一格是什么、也不知道怎么触发 ——
**这正是"发现"这件事的乐趣所在。**

**父名制和父系氏族的触发条件是我最满意的两个：**

> 有一个男人，他的孩子活下来了一大半。大家开始拿他的名认人。

不是"人口到 X"，而是**部落里真的出现了一个留下很多后代的男性** ——
父系氏族就是这么在现实里被"发现"的。

## 16.5 继嗣制度改由知识解锁

[docs/15](15-继嗣制度.md) 里的六种制度原来是按人口阶段解锁的。
现在**人口退化成触发条件之一**，真正的门是知识：

```
想做父系氏族？  →  得先有一个男人留下 6 个活后代，让你"想到"这件事，
                   还得先采纳父名制，再花 75 信仰学。
```

社会阶段（游团/氏族/酋邦）仍然显示在制度面板上，作为**背景描述**，
但不再是门槛。这样"制度是由经历发现的"这件事才落到实处。

## 16.6 设计红线（和 docs/14 同一条）

**每一项效果都必须在 sim 里有对应的读取点。** 单元测试直接验这条：

```gdscript
for id in Knowledge.ALL_IDS:
    for k in Knowledge.effects_of(id):
        if not Knowledge.EFFECT_TEXT.has(String(k)):
            no_text += 1
check(no_text == 0, "所有效果键都有中文说明")
```

效果键和读取点：

| 效果键 | 读在哪 |
|---|---|
| `food_mult` | `tick_day` 的每日口粮 |
| `granary_mult` | `granary_cap()` |
| `gather_mult` / `hunt_mult` | `_production_from_sites()` |
| `transit_forage` | 在途觅食 |
| `kin_avoid` | `Tribe._choose_mate` 的避亲项 |
| `defect_resist` | `Tribe.step` 的缺陷判定 |
| `faith_rate` | `_tick_faith_and_morale()` |
| `gene_flow` | 每年外来者判定 |
| `clan_exogamy` | `Tribe._choose_mate` 的同姓惩罚 |
| `planned_pairing` | 自动配对策略切换 |
| `force_pair_mercy` | 强制配对的士气代价 |

**界面上显示的是人话，不是键名**：

```
作用：粮仓上限 ×1.35
```

而不是 `granary_mult 1.35`。这是给玩家看的界面，不是给程序员看的调试面板。

## 16.7 单元测试里三条不变量

知识树的定义是数据，数据最容易出的错是**引用坏掉**和**永远触发不了**。
所以除了常规检查，专门加了三类：

1. **所有前置知识都存在**（没有指向不存在的 id）
2. **前置的层级严格小于自身**（不成环、不倒挂）
3. **所有触发条件都能被满足**（喂满统计计数器，每一项都该亮）

```gdscript
var full := {"gathered": 99999.0, "hunted": 99999.0, ...}
for id in Knowledge.ALL_IDS:
    if not Knowledge.trigger_met(id, full):
        unmet += 1
check(unmet == 0, "所有触发条件都能被满足", "永远触发不了的有 %d 项" % unmet)
```

> 第 3 条特别值：**"永远触发不了"是知识树最隐蔽的 bug** ——
> 界面上那一格静静地显示 `？？？`，没有任何报错，你甚至不会注意到它一直没亮。

## 16.9 遗留

- **知识不能被遗忘或替代。** 真实的制度会互相取代，这里只增不减。
- **没有"知道但故意不采纳"的代价。** 比如知道近交禁忌却不采纳，应该有人不满。
- **知识的发现没有代价。** 现在发现纯靠经历，但可以让"发现"本身也消耗注意力/信仰。
- **四个分支的深度不均**：血脉支只有 4 项，社会支有 9 项。
- 另见 [docs/17 可扩展性实测](17-可扩展性实测.md)：加一个知识节点实测只要 1 个文件 10 行。
