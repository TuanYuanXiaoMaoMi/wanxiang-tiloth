# 18 存档与确定性

> 存档不是"把变量写出去"那么简单 —— **难点在于漏字段不会报错**。
> 复现：
> ```bash
> ./tools/godot.sh --headless --script res://tools/run_tests.gd   # 含轨迹测试
> ```

## 18.1 补之前是什么样

[docs/17](17-可扩展性实测.md) 实测出来的窟窿：

| | 字段总数 | 进了存档 |
|---|---|---|
| `WorldState` | 41 | 20 |
| `Beast` | 31 | **8** |
| `Tribe` | 23 | **0** |

而且 **`WorldState` 根本没有 `from_dict()`** —— 存了读不回来。
整个部落（人、基因组、姓氏、性情、关系、个人史）都存不下来。

**根因不是懒，是结构**：存档是一份**手写的字段白名单**。
每加一个新系统，它的状态就悄悄掉出去，而没有任何东西会提醒你。

## 18.2 现在存了什么

| 对象 | 覆盖 |
|---|---|
| `Beast` | 全部 31 个字段（含 surname、descent_mode、traits、hobbies、mood、thought、story、partner_id、pending_*） |
| `Pedigree` | 父系表 + 各自近交系数（`_cache` 不存，它是纯缓存） |
| `Region` | 食物/猎物/木石晶药存量、退化进度 |
| `SiteMap` | 工作点定义（位置/类型/名额）；`workers` 不存，由 assignments 推出 |
| `Tribe` | 全部：beasts、next_id、relations、used_names、事件计数器、制度、知识开关 |
| `WorldState` | 全部 41 个字段 |
| **随机数状态** | `Genome.rng.seed` + `state` |

### `workers` 与 `_cache` 为什么不存

> **凡是能推出来的，就不要存两份。** 存两份迟早会不一致 ——
> 而且那种不一致极难查：读档后工作点上挂了几个已经不存在的人。

## 18.3 随机数状态：不存它，读档必分岔

`Genome.rng` 是全局的。**不保存它的 `state`，读档后的世界一定会和历史分岔** ——
而且分岔得很隐蔽：前几天看起来一样，突然某次生育的性别不同了。

```gdscript
"rng": {"seed": Genome.rng.seed, "state": Genome.rng.state},
```

> 顺带记一个副作用：因为 RNG 是全局的，**同时跑两个世界会互相污染随机流**。
> 轨迹测试里必须给两条轨迹各自管理 RNG 状态，否则测出来的差异是测试自己的错。

## 18.4 轨迹测试：唯一能抓出漏字段的方法

逐字段比对**没用** —— 你只能比对你想得起来的字段，
而漏掉的恰恰是你想不起来的那个。

所以换个问法：

> **存档后跑 8 回合，与读档后再跑 8 回合，两边必须完全相同。**

```gdscript
Genome.rng.state = rng_a["state"];  a.end_turn()
Genome.rng.state = rng_b["state"];  b.end_turn()
if _fingerprint(a) != _fingerprint(b):
    # 打出第一处不同的那一行，直接定位
```

`_fingerprint()` 把世界的全部状态压成一个字符串：
turn / 资源 / 信仰 / 士气 / 知识 / 统计 / 地区存量 / 工作点 / 指派 /
每个人的全部字段（含基因组血浓、F、缺陷）/ 关系网。

**任何一处漏存，两条轨迹在下一回合就会分开。** 这比逐字段比对强一个数量级。

### 这个测试真的会失败吗

一次就通过的测试很可疑，所以故意验证过：

| 故意删掉 | 结果 |
|---|---|
| `Beast.mood`（心情，影响劳动产出） | 第 1 回合分岔：食物 1070 vs 1079 |
| `Beast.traits`（性情，影响劳动与口粮） | 第 1 回合分岔：1070 vs 1133，**连行数都不同**（一边死了人） |

> **测不出问题的测试等于没有测试。** 加测试的时候，顺手也要证明它能失败。

## 18.5 棘轮测试：防止再烂一次

轨迹测试能抓出**影响模拟**的漏字段。但如果某个字段漏了、又恰好不影响 8 回合内的模拟呢？

再加一道结构性的检查：

```gdscript
for p in w.get_script().get_script_property_list():
    if saved.has(nm) or transient.has(nm) or nested.has(nm):
        continue
    undeclared.append(nm)
check(undeclared.is_empty(), "新增状态字段必须二选一：进 to_dict，或进显式清单")
```

三份清单，每份都要写清楚理由：

| 清单 | 含义 | 例 |
|---|---|---|
| `transient` | 能重建，或本来就该每局重来 | `region`（由 node_id 重建）、`assignments`（每回合重派） |
| `nested` | 存了，只是放在子字典里 | `first_*` → `to_dict()["timeline"]` |
| `known_unsaved` | **该存但还没存**（一笔写明白的债） | **现在是空的** |

还有一条配套检查：**清单里不许留已删除的僵尸字段**
（否则清单会越积越长，最后没人敢动）。

**`known_unsaved` 现在是空的 —— 债还清了。**
将来真要往里加，必须同时写清楚为什么它可以不存。

## 18.6 存盘格式

用 `FileAccess.store_var()` 而不是 JSON：

```gdscript
f.store_var(to_dict(), false)
```

理由：它会**原样处理 `Vector2` 与 `StringName`**。
用 JSON 就得为每种类型手写编解码，而那正是存档最容易出错的地方
（读回来变成 `{"x": 1, "y": 2}` 这样的字典，然后某个 `pos.x` 静默变成 null）。

存档位置 `user://wanxiang_save.dat` —— 不用 `res://`，因为打包后 `res://` 是只读的。

## 18.7 界面上

顶栏加了 **存档 / 读档**。没有存档文件时「读档」按钮自动灰掉
（点了没反应比灰着更让人困惑）。

读档后**必须清掉界面上的选中状态** —— 成员 id 全变了，
不清的话面板上会显示一个已经不存在的人。

## 18.8 遗留

- **没有版本号。** 存档里没写版本，格式一变就读不了旧档（现在会直接失败返回 false）。
  正式做的话该有个 `version` 字段 + 迁移表。
- **没有多存档槽。** 现在只有一个固定路径。
- **没有自动存档。** 回合结束时自动写一份是很自然的做法。
- **存档体积没测。** 一局几十人 × 全字段 + 个人史，估计在几十 KB 量级，
  但没实测；如果个人史无上限增长（现在是 40 条/人封顶）会是个问题。
